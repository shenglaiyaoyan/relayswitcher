## 方案取舍

- **整页编辑（采用）**：层级最清晰，有空间同时放 Provider 与模型，符合用户已确认的方向。
- 单侧边抽屉：方便比对列表，但复杂模型参数仍拥挤，放弃。
- 保留弹窗精修：改动小，但无法根治两层弹窗与保存心智负担，放弃。

## 一、Provider 列表

- **全局窗口标题栏和侧边栏原样保留，不在本次设计范围**：不得重命名导航、添加计数/辅助标签、改品牌、改变宽度或重排底部状态与「关于与更新」。沿用现有 224px `.side`、斜体 RelaySwitcher wordmark、五项原导航及底部状态胶囊。
- OpenCode 为当前页，仅设计右侧主内容区。
- 页头保留斜体 `OpenCode` 大标题，正常功能标题使用 Inter / Microsoft YaHei。
- 主操作为「新建 Provider」，设置入口保留在页头。
- Provider 使用对齐的列表/表格行：名称与 ID、协议、模型数、默认模型、编辑、移除。
- 空状态与拉取/导入失败沿用现有能力，不为了视觉稿虚构状态。
- 列表只承担浏览与入口，不再用 Provider 行承载模型编辑。

## 二、整页 Provider 编辑

点击新建/编辑后，从列表切换到同一 OpenCode 页内的编辑工作区；返回可回列表。没有 Provider Modal，也没有叠加的 Model Modal。

### 接入与标识：全部手动输入

**新逻辑：移除中转站关联下拉框以及“已关联”“从现有中转站重新填入”入口。**

保留字段：

- Base URL：文本输入，现有保存时自动补 `/v1` 的规则不变。
- API Key：密码输入；编辑已有 Provider 时留空仍表示保持原 key。
- 协议：Messages / Chat / Responses 单选。
- Provider ID：文本输入。
- 显示名称：文本输入。
- 「从 /v1/models 拉取」：只使用当前表单手动输入的 Base URL 和 API Key。

历史数据边界：不删除已有 Provider 中可能存在的 `relayId` 等未编辑字段，不在本次迁移数据或重写 OpenCode 配置。这里只是取消 UI 的站库选择与自动回填，避免无关功能回归。

### 模型工作区

- 左侧为模型列表：ID/名称、简化的上下文与 effort 元数据、当前选中态、添加模型。
- 右侧为当前模型参数编辑区；点击左侧模型即切换，不打开第二层容器。
- 拉取到的模型仍可在列表区域提供勾选/添加入口，但不得恢复中转站关联下拉框。
- 默认模型选择能力保留，作为 Provider 编辑工作区中的一个明确字段，不因视觉稿漏画而删除。
- 删除模型需要确认；删除 Provider 的现有备份与确认行为保留。

## 三、模型参数编辑

- 模型 ID、显示名、上下文窗口、最大输出。
- 推理、附件、工具、Temp 开关，点击整个控件可切换，避免行与开关双触发。
- 输入/输出模态：text、image、audio、video、pdf。
- 思考档位：点击已有档位选择/取消默认；新增档位使用**显式 `type="text"`** 的受控输入框，白字即时可见。Enter 或失焦确认，Escape 取消；空白与重复项不新增。
- 「套用推荐参数」保持一次性填入表单，不恢复会覆盖用户参数的“跟随推荐”状态。
- 连接区可在模型参数编辑时收起为一行摘要，并可展开编辑；不是必须新增的另一套路由。

## 四、统一草稿、保存与退出

- 整个 Provider（含其所有模型）共享一份编辑草稿。
- 模型字段的改动直接更新 Provider 草稿，不再有单独「保存模型」按钮。
- 底部固定操作栏显示未保存状态，提供取消/返回与「保存并写入 OpenCode 配置」。
- 点击保存时先验证 Provider ID 非空；沿用现有行为过滤空 ID 的模型行，不要求 Provider 必须有模型。保存失败保留草稿并显示错误。
- 有改动时，返回、取消或切换侧边导航需要确认放弃；未改动直接返回。
- 保存成功后才退出编辑态并刷新列表；保存失败留在当前草稿，不能丢输入。
- 模型切换不需要逐个弹“保存模型”提示，因为改动已经属于统一草稿。

## 五、视觉与组件边界

- 正常中文/英文 UI 与「编辑 Provider」标题：Inter / Microsoft YaHei，禁止斜体衬线。
- Playfair Display italic 仅用于 `OpenCode` 页面标题；等宽字体仅用于 ID、URL、技术数值。
- 使用现有颜色、按钮、输入框、Select、Toggle、Confirm、Icon 组件，新增工作区所需的最小 CSS。
- `OpenCode.jsx` 当前已承载列表、Provider 表单和模型弹窗。实施时按职责拆分列表、整页 Provider 编辑、模型参数编辑及可测的草稿辅助逻辑，避免继续在一个组件里叠加状态。
- 不改 `electron/lib/opencode.js` 的原生 V2 配置写入规则，不改 OpenCode 运行服务，不修改用户真实 `opencode.jsonc` 作为界面验收的一部分。

## 六、测试与验收

1. 先写失败测试，覆盖手动输入拉模型、无站库下拉、模型草稿切换/增删、统一保存和未保存退出确认。
2. 真实 Electron 中检查列表 → 新建/编辑 → 模型切换 → 参数修改 → 保存/取消路径，无叠加弹窗。
3. 新增档位输入 `xhigh` 且不按 Enter 时，文字即时可见；Enter、blur、Escape 行为符合原约定。
4. 保存失败不丢草稿；确认放弃才丢弃改动。
5. 原生 V2 写入单测保持通过；UI 验收使用隔离临时 HOME/配置，不触碰另一对话维护的真实配置。
6. 全量单测、Vite 构建、39 项 smoke、图标/快捷方式及 Release 资产验证按既有发布流程执行。

## 不在本次范围

- 不改 ChatGPT、中转站、备份、设置等其他页面。
- 不新增协议、Provider 类型或模型能力。
- 不迁移站库、不删除历史关联数据。
- 不擅自添加新的保存后运行验证、自动重启或远程调用。
